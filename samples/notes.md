# 现场记录

随手记的，回头看能少走点弯路。

- 出事那次是缓存过期的一瞬间：同一个商品键上一下子压了几十个请求，全都没命中，一起打去后端，连接池当场被打满，
  后面连正常的请求也进不来了。日志里几十条一模一样的下游调用，连参数都一模一样。
- 后端那一次要是失败，等着的那几个请求就一起失败，别自己偷偷再打一遍；用户要重试是用户的事。
- 有人点了取消、有人等到超时就走，走掉的请求不该再拿到结果；发起者自己也可能是先走的那个。
- 同时打后端的键数得有个上限，一个键上排队的人数也得有上限，超了就当场拒掉，别排队干等。
- 现场是客户的机器，装不了东西：没有外网、pip 也拉不动，只能用 Python 自带的标准库。页面也只要浏览器原生那
  一套，双击能打开就行。
- 时间这块没法真等，希望能用一份带时刻的脚本描述「什么时候来了哪个请求、这次跑了多久、谁取消了」，跑出来的
  轨迹每次都要一模一样，方便逐行比对。
- 交付前对方强调过：同一份脚本跑两遍，轨迹必须逐字相同。
